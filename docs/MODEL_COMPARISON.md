# Model comparison and model-selection protocol (what every reported number means)

All numbers below are **test-split results on the same 12 held-out synthetic patients, the same target
definition and the same patient-level protocol** unless an experiment is explicitly named as a variant.
Everything is regenerated by committed code (`make train`, `glucotwin audit`,
`scripts/ablate_record_features.py`); nothing is typed by hand. All patients are synthetic — these are
upper bounds that describe our simulator, not clinical validation.

## 1. The three event-model AUROCs (0.884 / 0.9075 / 0.936) are three different experiments

| # | AUROC | Experiment | Model | Feature set | Served? | Source of truth |
|---|---|---|---|---|---|---|
| E1 | **0.884** (CI 0.839–0.923) | Main pipeline, test split | Logistic regression (C=0.5, standardised) | All 33 features incl. the 10 direct record features | ✅ served (threshold 0.35, chosen on validation) | `reports/evaluation_report.json` → `event[logistic_regression]` |
| E2 | **0.9075** | Ablation variant (2026-10-20): identical protocol, record features removed | Same logistic class | 23 dynamic features only | ❌ experiment only | `docs/ABLATION_RECORD_FEATURES.md`, `scripts/ablate_record_features.py` (Δ vs E1 bootstrap CI −0.053..−0.001) |
| E3 | **0.936** (CI 0.915–0.955) | Main pipeline, test split | Histogram gradient boosting | All 33 features | ❌ reported alternative (threshold 0.32) | `reports/evaluation_report.json` → `event[hist_gradient_boosting]` |

They are **not contradictory**: E2 changes the feature set (not the split or target), E3 changes the model
class. E3 discriminates better than the served logistic on test, but logistic is served because its grouped
additive contributions are **exact** (no SHAP approximation, no extra dependency) and drive the dashboard's
"What drives this estimate" panel; gradient boosting is reported for comparison and is on the roadmap only
with a proper explanation layer. E2's gain is real on test but **not selectable on validation**
(0.8881 with vs 0.8866 without), so per the frozen protocol the served feature set is unchanged — details
and the mechanism (`fasting_glucose_mg_dl`, std-coef ≈ −3.7) are in `docs/ABLATION_RECORD_FEATURES.md`.

Supporting metrics (test, main pipeline): trend-rule baseline AUROC 0.655 / AUPRC 0.324 / 6.3 false
alert-episodes per patient-day; logistic 0.884 / 0.668 / 1.36, sens 0.665, spec 0.902, PPV 0.538, median
lead 95 min (sustained-warning audit: 69% of onsets, 95% CI 0.48–0.83); gradient boosting 0.936 / 0.756 /
1.07, sens 0.783, spec 0.901, PPV 0.575, lead 120 min (horizon-capped). Calibration is reported via Brier
(logistic 0.082, GB 0.069) and the 80% conformal interval coverage (0.76–0.80 across horizons).

## 2. Ridge vs gradient boosting, glucose trajectory, every horizon (test RMSE, mg/dL)

| Model | 30 min | 60 min | 90 min | 120 min |
|---|---|---|---|---|
| Persistence | 18.7 | 31.4 | 40.7 | 46.6 |
| Damped trend | 17.4 | 31.1 | 42.5 | 50.4 |
| Ridge | 11.2 | **17.0** | 23.6 | 27.9 |
| **Hist gradient boosting (served)** | **10.4** | 17.2 | **22.9** | **25.9** |

**The 60-minute horizon is a genuine near-tie with a slight Ridge edge (17.0 vs 17.2).** The served model
was chosen on **mean validation RMSE across all four horizons** (GB 19.8 vs Ridge 23.0), not per-horizon
test peaks; that is the pre-registered selection rule, and we do not retune it post hoc. Practical reading:
the two models are statistically indistinguishable at 60 min on 12 test patients; GB's advantage concentrates
at 30 and 120 min. This comparison is documented rather than "fixed" because switching trajectory models
per-horizon would complicate the API contract and the conformal-interval story for no verified benefit.

## 3. Model-selection protocol (frozen; applies to any future change)

1. Patient-level split 36/12/12 by seeded permutation; no patient in two splits (`test_leakage`).
2. Fit on train only; all thresholds and conformal widths on **validation**; **test is scored once** per
   candidate and never used for selection.
3. Report validation alongside test for any candidate (a test-only gain is not selectable — see E2).
4. Any adopted change must regenerate `reports/evaluation_report.json` (deterministic) and the deck numbers
   in the same change, and must state model, split, feature set, target, metrics and selection rule.
5. Held-out performance on synthetic patients is an upper bound; never described as clinical validation.

## 4. Known small-sample caveats

12 test patients → wide CIs (sustained-warning sensitivity CI 0.48–0.83); single cohort seed for the served
model (3 other seeds audited: AUROC 0.883–0.910); single simulator, whose meal-response shape the models can
partly rediscover. These are stated wherever results are shown.
