# Testing, security and reliability plan (Agent F)

## Conventions

* `pytest` with test files mirroring modules (`tests/test_<module>.py`). Shared fixtures live in `tests/conftest.py`: a small deterministic
  cohort (10 patients × 4 days, seed 1234) and a real pipeline run on it, so the suite exercises real code paths in about 10 s.
* No mocks of our own modules in integration tests. API tests use FastAPI's `TestClient` against a real `TwinService`.
* Every new feature lands with a test. Every bug fix lands with a regression test.
* Lint with `ruff` (pyflakes, pycodestyle, isort, bugbear, pyupgrade). The frontend is type-checked by `tsc -b` during the build.

The leakage tests were themselves validated by mutation. Injecting a 30-minute future shift into one feature made two tests fail.

## Critical failure scenarios and coverage

| Scenario | Handling | Test |
|---|---|---|
| CGM dropout / sensor gap | Gaps break runs and lines; forecast withheld if fewer than 6 readings in 60 min; staleness flag after 20 min | engine, labels |
| Duplicate delivery | Idempotent | engine |
| Out-of-order or late data | Rejected with a reason (re-sorting is a backlog item) | engine |
| Naive or local timestamps | 422 at the boundary | contracts, API |
| Impossible values / wrong units | Rejected per item, rest of batch accepted | engine, API |
| Glucose already high | No onset risk issued; trajectory still shown | engine |
| End of record | Labels unknown, not negative | labels |
| Distribution shift between splits | Reported (prevalence by split) | report |
| Concurrent requests | Service-level RLock | (manual) |

## Release checks (minimum before tagging or submitting)

```bash
make check     # ruff + pytest + frontend typecheck/build
make train     # regenerates reports/evaluation_report.json deterministically
```
1. All tests pass, and ruff is clean.
2. `reports/evaluation_report.json` was regenerated by the committed code, and numbers in the README match it.
3. The dashboard loads with no console errors (verified with headless Chromium for v0.1).
4. `git grep` finds no real identifiers; `data/` and `artifacts/` are ignored.
5. Dependencies are within the constraints of `pyproject.toml`; `requirements.lock` and `frontend/package-lock.json` are committed.

## Privacy and security review

* **No real patient data** is used or committed. Identifiers are forced to the `SYN-` prefix. Names are synthetic and suffixed "(synthetic)".
* `data/` (for optional external datasets) is git-ignored. External raw data must stay local and keep its licence.
* **Pickle** model bundles are loaded only from the local `artifacts/` directory produced by `glucotwin train`. Never load a bundle
  from an untrusted source (documented in `ModelBundle.load`).
* The API has **no authentication**. It is a local demo, not for deployment with real data. Real deployment would need authN/Z, TLS,
  audit logging, rate limiting, and DPDP Act 2023 compliance review.
* Request size is bounded (≤ 5,000 observations per batch, list endpoints capped). Pydantic validates every request body.
* The frontend uses relative URLs only. There are no secrets in the bundle and no third-party calls at runtime.
* Supply chain: few direct dependencies (6 runtime Python, 3 runtime JS). Versions are constrained, and lock files are committed.
  Known deprecation: Starlette's `TestClient` warns that `httpx` support is deprecated. It is test-only; track it (B-14).

## Reproducibility

* Every random draw flows from one seed, and the cohort, splits, models (`random_state`) and report are deterministic. Two full runs on 2026-10-17
  produced identical metrics.
* `requirements.lock` pins the exact Python environment used for the reported numbers (Python 3.11.2).

## Wave-2 security checks (2026-10-17)

* `pip-audit -r requirements.lock`: initially found **PYSEC-2026-1845 / CVE-2025-71176** in pytest 8.4.2 (dev-only tmpdir handling, CVSS 6.8).
  Upgraded to pytest 9.1.1, after which no known vulnerabilities were found. `npm audit` (frontend, including dev): 0 vulnerabilities.
* Probes against the running API: path-traversal-style IDs give 404; huge replay offsets gave **500** (fixed, now 422); replay of training
  patients was allowed (fixed, now 404). There is no CORS middleware, so the app is same-origin only. Secret scan of tracked files found nothing.
* Synthetic-identity safeguards: IDs must match `SYN-####` (schema-enforced), names carry "(synthetic)", `is_synthetic: true` is a literal in
  the record contract, and every forecast carries a disclaimer.
